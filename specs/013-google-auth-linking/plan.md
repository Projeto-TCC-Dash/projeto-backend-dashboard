# Implementation Plan: Feature 013 Vínculo de Contas Sociais — Google OAuth 2.0

**Branch**: `013-google-auth-linking` | **Date**: 2026-10-24 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/013-google-auth-linking/spec.md`

## Summary

Implementação do vínculo de contas sociais com o Google (OAuth 2.0 / Google Identity Services) na API REST do backend financeiro. Fornece endpoints para vincular (`POST /api/auth/google/link`), desvincular com regra de guarda contra perda acidental de acesso (`DELETE /api/auth/google/unlink`) e realizar login autenticado por conta Google (`POST /api/auth/google`), interoperável com o perfil de usuário (Feature 011).

## Technical Context

**Language/Version**: Node.js 20+ com TypeScript em modo estrito (`strict: true`, `noImplicitAny: true`, `strictNullChecks: true`)

**Primary Dependencies**: Fastify 4.x/5.x, `fastify-type-provider-zod`, Zod 3.x, `@fastify/jwt`, Mongoose 8.x, native `fetch` (Node 20+)

**Storage**: MongoDB nativo gerenciado via Mongoose ODM (subdocumento `googleAccount` no `UserSchema` com índice esparso único em `googleAccount.googleId`)

**Testing**: Vitest (`vitest run`), supertest / fastify inject para testes de integração e unitários

**Target Platform**: Linux / Docker Compose, multi-stage build

**Project Type**: REST Web Service

**Performance Goals**: Tempo de resposta de validação e vinculação < 1.5s; resolução em memória sem introdução de bloqueios I/O desnecessários

**Constraints**:
- Zero dependências de bancos relacionais
- Não persistir nem expor tokens sensíveis do Google em logs
- Conformidade estrita com LGPD (princípio de minimização de dados)
- Garantir guarda contra lock-out: rejeitar desvinculação se o usuário não possuir senha local cadastrada

**Scale/Scope**: Módulo de autenticação social complementar a e-mail/senha
